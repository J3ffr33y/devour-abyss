# 2.5D 方案

> 2026-10-28 定（DEC-041）。画面用 3D 渲染，玩法在一个横向平面里进行。和其他篇冲突时以本篇为准。
> 画面参考：`prototype/visual-2.5d/`。手感参考：`prototype/feel/`。

## 1. 一句话

玩家在一个竖直平面里游动（和 2D 原型完全一样的操作），但世界、生物和镜头都是 3D 的：背景有纵深，巨兽可以从深处游过、从背景浮到玩家的平面里来。

## 2. 引擎

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| **Godot 4（推荐）** | 免费、无分成；场景和脚本都是纯文本，AI 工具可以直接读写；3D 渲染足够 2.5D 使用 | 现成 3D 素材比 Unity 少 |
| Unity | 素材商店丰富，水体和鱼类素材能直接买 | 有收费政策风险；工程对 AI 工具不如 Godot 友好 |

## 3. 玩法平面与纵深

- **玩法平面**：玩家、可吞噬的猎物、会攻击玩家的敌人，碰撞判定都在 z = 0 平面上。
- **背景层**（z < 0）：装饰鱼群、远处地形、遗迹、路过的巨兽。只看不碰。
- **前景层**（z > 0）：少量岩石、海草、浮游物，增加纵深，不挡关键视线。
- **跨层登场**：重要敌人可以先在背景层出现，再游进玩法平面（2.5D 演示里的掠食者就是这样）。这是 2.5D 最有价值的表现手段，用来实现第 15 章「先预警、再露局部、最后正面接触」的节奏。
- **撤退规则**：掠食者追击超时后沉回背景层（DEC-036），玩家能直接看到它离开。

## 4. 镜头

- 默认侧视，带轻微透视；跟随玩家，带前瞻。
- 玩家变大时镜头拉远。
- Boss 战和巨兽登场时可以短暂换成斜俯视或拉远的镜头，但不剥夺操作。
- 关卡里的岔路和上下分层仍按 2D 关卡设计，不需要 3D 寻路。

## 5. 美术流程（一人 + AI）

- **风格**：低多边形 + 强雾 + 生物发光。暗环境能藏住模型粗糙，也最省工作量。
- **模型**：AI 生成 3D 初模 → Blender 减面、清理 → 导出 glb 进 Godot。详细工具链见 `docs/art-pipeline/`。
- **动画**：鱼、鳗、蛇形用着色器或程序动画摆动；只给 Boss 做少量关键帧动画。
- **器官外观**：器官做成挂点上的独立小模型（鳍、发光器、甲片），换器官就是换挂件。
- **省力点**：背景生物只从侧面被看到，模型背面和细节可以很粗；远景可以直接用剪影。

## 7. 里程碑

1. **Godot 工程骨架 + 手感移植（1–2 周）**：把 2D 原型的游动、吞噬、掠食者、撤退规则搬进 Godot 的 2.5D 场景，参数保持一致。
   - 2026-10-28：骨架完成，见 `game/`。待 Jeffrey 在本机试玩确认手感。
2. **美术流程验证（2 周）**：用 AI 工具做出一条可用的鱼和一个掠食者，跑通生成到进引擎的流程，记录每个模型花多久。
3. **器官与成长（3–4 周）**：6 个器官、体型成长、镜头随体型变化。
4. **垂直切片（6–8 周）**：遗忘之海 + 白骨巨鲨，按第 15 章的五步登场节奏。用来做 Steam 商店页和预告片。
5. **完整首版（剩余时间）**：补完海域、记忆碎片、结局、打磨。

第 1、2 步完成后再评估一次总工期，明显超出就砍内容，不拖上线时间。

## 8. 风险

- 3D 模型的产出速度决定整体进度，第 2 步要量出真实耗时。
- 背景层内容很容易越做越多，每个区域给背景层定一个数量上限。
- 前景遮挡和透视会影响可读性，玩法平面上的关键物体要始终清楚。
